# Guoba（锅巴）设置页完整使用手册

本文覆盖荷花插件设置页的全部项目。路径：锅巴后台 → 插件管理 → Lotus-Plugin/荷花插件 → 设置。

## 使用步骤

1. 使用 #锅巴登陆进入后台，打开荷花插件设置页。
2. 按项目下方说明填写；多行输入框每行填写一项。
3. 周期任务的周期、间隔、时间只能选一种周期；每天使用 HH:mm:ss，每周/每月在后面加周期日。每小时/每分钟模式的时间填写“无需填写”。
4. 保存后刷新页面。周期任务、验证码服务、冲突路由、Python 和工具链修改后重启 Yunzai。
5. 计划生成看 schedule ready，签到执行看 scheduled checkin executed。

## 重要配置示例

### 每天 23:30 生成次日随机计划

生成计划：每天 / 1 / 23:30:00；当日/次日分界：23:00；模式：随机；随机窗口：00:20-01:20；到期扫描：每分钟 / 5 / 无需填写；补偿检查：每分钟 / 5 / 无需填写。保存后重启 Yunzai。

### 固定签到

选择固定时间，填写全局固定签到时间 HH:mm。profile 单独设置固定时间时，以 profile 设置为准。

## Q这些设置不能随便填写

### 周期与扫描
计划生成只负责把 profile 写入日期计划文件；到期扫描才负责执行签到。因此随机窗口是 00:20-01:20 时，到期扫描必须在这段时间内反复运行，不能只设置每天 00:00 扫描。计划补偿只负责补建漏掉的计划，不会代替到期扫描。修改周期后要重启 Yunzai，因为定时任务在插件启动时注册。

### 随机与固定模式
随机模式把多个 profile 分散到窗口内，目的是避免所有账号同时请求米游社接口；固定模式适合希望每天在同一时间执行的账号。profile 级固定时间优先于全局时间，是为了让不同账号可以独立安排。

### 背景池与超分
背景池把网络图片提前下载到本地，生成状态图时不再等待远程接口，因此可以降低消息延迟。保留数量和单图大小决定磁盘占用；超分档位决定渲染清晰度和 CPU/内存消耗，软路由通常选择关闭或低档。

### 验证码提供方
验证码提供方按列表从上到下尝试。把稳定、延迟低的方案放前面可以减少等待；保留人工方案作为末级兜底可以避免自动方案全部失败后流程中断。接口地址、密钥和模型目录必须能从容器内部访问。

### Python 与工具链
虚拟环境用于隔离荷花依赖，系统 Python 适合已有统一运行环境的用户。BBDown、ffmpeg、aria2 分别负责获取媒体、处理媒体和加速下载；目录或命令填错时，插件即使配置保存成功也无法执行外部程序。

### 权限与远程管理
权限项目决定“谁能做什么”，默认策略、用户/群名单和功能范围会共同生效。远程管理涉及命令和文件，应先限制路径、大小、Shell 和超时，再按需开启 OTP；这样可以避免普通消息触发高权限操作。

## 设置项逐项说明

## 兼容模式（重叠命令中荷花固定末位）

查询、面板等重叠用户命令固定由其他插件先处理，Lotus 仅作末位兜底，因此设置页不提供普通命令接管开关。旧配置中的 `compatibility.conflict_takeover` 仅为兼容读取而保留，任何取值都不会改变普通命令优先级。合并或升级时按[重叠命令优先级检查清单](command-priority-policy.md)复核。

### 验证码优先路由（compatibility.captcha_priority_takeover）

- 控件：Switch
- 用途：默认开启。仅让荷花优先处理米游社验证码，自动识别失败后仍由其他插件兜底；不会禁用其他插件。修改后需要重启 Yunzai。
- 操作：修改后点击保存；若属于定时、服务启动或运行环境项目，再重启 Yunzai 并查看日志确认。
- Q：这个开关决定功能是否参与运行；关闭可以减少资源消耗或避免功能与现有插件、服务产生冲突。只有在需要该功能时开启。

## B站磁盘清理

### 启用自动清理（bilibili.cleanup.enable）

- 控件：Switch
- 用途：统一控制B站临时目录、成品目录和缓存清单的自动清理。
- 操作：当前节省磁盘方案保持开启。关闭后，启动清理、定时清理和发送后删除均不会执行。
- Q：这是整个B站清理链路的总开关。关闭它不会关闭视频解析或下载，但异常中断留下的临时文件和下载成品可能持续累积。

### 启动时清理（bilibili.cleanup.startup）

- 控件：Switch
- 用途：Yunzai 启动约60秒后执行一次兜底清理。
- 操作：建议保持开启，让容器重启后自动处理上次异常退出遗留的文件。
- Q：延迟60秒是为了避开插件集中加载阶段。它遵守临时文件保留时间、成品保留天数和容量上限，不会直接清空整个插件目录。

### 清理时间（bilibili.cleanup.cron）

- 控件：周期下拉框、间隔数字框、24小时时间框
- 用途：设置兜底清理任务的执行周期；锅巴负责转换，后端继续保存7位 Cron。
- 操作：当前选择“每天”，时间填写 `04:20:00`。不需要手工填写 Cron。
- Q：每天04:20用于处理没有走到发送后删除、进程异常退出或文件句柄暂时占用时遗留的文件，并避开04:10的攻略作者库刷新。它只扫描 `data/bilibili/`，不会执行签到或清理其他插件。

### 发送后删除（bilibili.cleanup.delete_after_send）

- 控件：Switch
- 用途：等待视频消息、群文件或好友文件发送调用结束后删除本次本地成品。
- 操作：当前节省磁盘方案保持开启，同时关闭“启用下载缓存”。
- Q：开启后重复请求需要重新下载，但磁盘占用最低。若要复用下载成品，应关闭本项并开启下载缓存，不能把两个策略同时开启。

### 成品保留天数（bilibili.cleanup.retention_days）

- 控件：InputNumber
- 用途：定时清理时删除超过指定天数的下载成品；`0` 表示不按年龄删除。
- 操作：当前填写 `1`，作为发送后删除失败时的兜底。
- Q：正常发送后文件会立即删除，所以此值主要处理异常残留。设置为0时仍受容量上限约束。

### 临时文件保留小时（bilibili.cleanup.tmp_retention_hours）

- 控件：InputNumber
- 用途：清除 `data/bilibili/tmp` 中超过指定小时的未完成下载任务；`0` 表示清理时移除全部临时任务。
- 操作：当前填写 `6`，避免清理仍可能在执行的长视频任务。
- Q：临时目录不是可复用缓存。保留数小时可以容忍慢下载和文件句柄延迟释放，同时避免中断任务长期占用磁盘。

### 成品容量上限（bilibili.cleanup.max_total_size_mb）

- 控件：InputNumber
- 用途：限制 `data/bilibili/downloads` 的总容量，超限时从最旧文件开始删除；`0` 表示不限。
- 操作：当前填写 `1024`，即1GB兜底上限。
- Q：该上限主要应对发送失败、程序中断或文件暂时无法删除的情况。它不会限制单个视频的下载大小；单个视频的发送形式由“发送大小限制”控制。

## 故障排查顺序


1. 检查开关、路径和数值格式。
2. 周期任务先确认计划文件已生成，再确认到期扫描覆盖任务窗口。
3. 保存周期配置后重启 Yunzai，避免旧 Cron 继续运行。
4. 验证码按尝试顺序检查接口、密钥、超时和模型目录。
5. 工具链先执行初始化命令，再检查 Python、BBDown、ffmpeg、aria2 路径。
6. 权限问题检查默认策略、用户/群名单和权限范围。
