# 三游戏攻略本地缓存与增量刷新

返回：[文档目录](../README.md) / [小功能索引](README.md) / [指令索引](../commands.md)

## 功能目标

Lotus 会把指定米游社作者的攻略索引持久化到本机，不在每次查询时重新下载作者的全部历史文章。缓存文件为：

```text
plugins/Lotus-Plugin/data/strategy-authors/cache.json
```

缓存包含作者、文章 ID、游戏分区、标题、正文摘要、话题、攻略图片地址、文章创建/更新时间和最近检查时间。QQ 返回消息仍带米游社原文链接；图片由消息发送组件按缓存中的地址读取。图片文件本身不做全量落盘：当前 33,622 个去重图片地址按抽样均值估算约需 55 GiB，本地化收益不足以覆盖存储开销。

`cache.json` 是实例运行数据，不需要提交到 Git。重启 Yunzai、更新插件或者暂时断网都不会清空它。不要为了普通更新手工删除该文件，否则下一次刷新会重新执行首次全量建库。

## 首次建立本地库

首次安装时本地没有已知文章 ID，Lotus 会分页读取各作者的历史文章，并原子写入缓存：先生成同目录临时文件，完整写入后再替换 `cache.json`。这样进程中断时不会留下半份 JSON。

主人可发送：

```text
#更新攻略作者库
```

首次结果中的“本地共 N 篇”是该作者已经落盘的文章数；“读取 N 页”是本次实际访问的接口页数。

## 后续增量刷新

本地已有缓存后，定时任务和手动更新都使用同一套增量算法：

1. 从作者最新一页开始读取。
2. 新文章 ID 不在本地时，追加到本地库。
3. 已存在文章的标题、正文、话题、图片或更新时间发生变化时，覆盖该文章的本地记录并计为“更新”。
4. 当前页末端落入本地已知文章后停止翻页；更早的历史文章继续使用本地记录。置顶旧文章不会被误判成增量边界。
5. 按创建时间重新排序并原子落盘，不删除旧攻略。

因此日常刷新通常只读取每位作者一页。只有首次建库，或者作者一次发布的新内容超过一页且尚未遇到本地边界时，才会继续翻页。作者请求以最多 3 路并发执行，不再逐个串行等待；多个刷新任务仍会排队写缓存，避免相互覆盖。

## 定时刷新

Lotus 当前后端任务为：

```text
0 10 4,16 * * ? *
```

即按 Yunzai 进程时区每天 `04:10` 和 `16:10` 各执行一次增量检查。若容器使用 UTC，则对应北京时间 `12:10` 和次日 `00:10`。判断实际时间时以容器内 `date` 和启动日志为准。

日志会显示成功作者数、失败作者数、新增文章数和更新文章数，例如：

```text
[Lotus-Plugin] strategy cache incrementally refreshed: 8 succeeded, 0 failed, 2 added, 1 updated
```

## 查询时检查更新

作者数据的新鲜期为 **12 小时**。用户发送 `#角色攻略`、`*角色攻略` 或 `%角色攻略` 时按以下顺序处理：

1. 先从进程内存中的已解析缓存匹配，避免每次重新解析约 6.9 MB 的 JSON。
2. 作者最近成功检查时间不足 12 小时时直接返回，不访问米游社作者接口。
3. 缓存超过 12 小时但已有匹配攻略时，立即返回本地结果，同时在后台并行增量刷新相关作者；下一次查询使用新数据。
4. 缓存超过 12 小时且当前没有匹配攻略时，等待一次并行增量刷新后重新匹配，避免刚发布的新角色被旧缓存误判为不存在。
5. 首次安装没有可用作者数据时等待首次建库，不能用空缓存回答。

定时任务仍每天执行两次，主人发送 `#更新攻略作者库` 仍会立即强制检查全部作者，不受 12 小时新鲜期限制。

如果接口临时失败，查询会继续读取已有本地缓存：

- 本地有匹配内容：立即返回旧缓存；后台刷新失败只写日志，不影响本次回复。
- 本地没有匹配内容：返回未找到，并提示有多少作者源暂时请求失败。
- 某个作者刷新失败：保留该作者原缓存，不用空结果覆盖。

2026-08-25 优化前的分段实测为：纯本地匹配约 136 ms，查询前同步刷新约 2,407 ms，所选两张图片下载约 330 ms。主要延迟来自每次查询都串行刷新 3 位作者，而不是图片传输；12 小时新鲜期、后台刷新、3 路并发和内存缓存正是针对这一瓶颈。

## 返回字段说明

手动执行 `#更新攻略作者库` 后，每个作者会显示：

- `新增`：本次发现的新文章 ID 数。
- `更新`：文章 ID 相同但内容发生变化的数量。
- `本地共`：该作者当前持久化的文章总数。
- `读取`：本次增量检查访问的接口页数。
- `已保留本地旧缓存`：本次请求失败，但本地数据仍然可用。

## 验证与故障处理

检查缓存存在且 JSON 可读取：

```bash
cd /root/Yunzai
test -s plugins/Lotus-Plugin/data/strategy-authors/cache.json
node -e "const fs=require('fs');const p='plugins/Lotus-Plugin/data/strategy-authors/cache.json';const d=JSON.parse(fs.readFileSync(p));console.log({version:d.version,updatedAt:d.updatedAt,authors:Object.keys(d.authors||{}).length})"
```

验证增量边界：连续执行两次 `#更新攻略作者库`。没有新内容时，第二次应主要显示“新增 0、更新 0、读取 1 页”，不应重新遍历全部历史页。

查看相关日志：

```bash
docker logs --since 30m trss-yunzai 2>&1 | grep -E 'strategy cache|攻略作者库|三游戏攻略'
```

接口异常时先保留缓存并检查网络，不要立即删库。确实需要重建时，先备份再删除：

```bash
cd /root/Yunzai/plugins/Lotus-Plugin
cp -a data/strategy-authors/cache.json "data/strategy-authors/cache.json.bak.$(date +%Y%m%d%H%M%S)"
rm data/strategy-authors/cache.json
```

随后发送 `#更新攻略作者库` 重新完成首次建库。
