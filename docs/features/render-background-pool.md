# 渲染超分档位与本地背景池

## 设计目标

荷花插件不再在每次生成图片时请求随机图接口。插件启动时若未找到可用图片池，会自动完成接口测速和首次下载；此后渲染只读取本地文件。每日定时任务重新测速全部接口，使用测速最快的可用接口优先下载 10 张不重复图片。

新批次完整写入并更新清单后，旧批次会保留约 60 秒的渲染宽限期再自动删除，避免正在生成的图片仍引用旧文件。测速或下载失败时不会破坏上一批图片，因此网络故障不会阻塞已有本地背景的渲染。

## 锅巴设置

在「荷花插件 → 渲染」中可配置：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 随机背景接口 | 5 个候选接口 | 每次更新都并行测速，按实际图片下载耗时排序 |
| 启用本地背景池 | 开启 | 关闭时只使用列表中的本地路径 |
| 本地背景数量 | 10 | 允许 1～50，建议保持 10 |
| 背景更新时间 | 每天 04:10 | Quartz cron；修改后重启 Yunzai 让任务时间重新注册 |
| 背景加载超时 | 3000 ms | 单次接口或图片请求的超时 |
| 单接口下载重试 | 4 | 遇到重复图片或网络失败时继续尝试 |
| 更新失败自动重试 | 开启 | 完整批次更新失败后继续使用旧图片，并在当天退避重试 |
| 失败重试间隔 | 10、30、60 分钟 | 每次重试仍失败后，依次等待这些时长再试 |
| 单图体积上限 | 20971520 字节 | 防止异常接口返回超大文件 |
| 超分辨率档位 | 关闭（1x） | 低 1.5x、中 2x、高 3x、极高 4x |

超分档位控制 Skia 画布输出倍率。像素量近似按倍率平方增长，例如 2x 约为 1x 的 4 倍像素，4x 约为 16 倍；资源较紧张的 Docker 建议关闭或使用低档。

对应 `global.yaml`：

```yaml
render:
  background:
    - https://example.invalid/random-image-api
  background_timeout_ms: 3000
  background_pool_enable: true
  background_pool_size: 10
  background_refresh_cron: "0 10 4 * * ? *"
  background_download_retries: 4
  background_retry_enable: true
  background_retry_delays_minutes: [10, 30, 60]
  background_max_bytes: 20971520
  super_resolution_preset: off
```

## 本地目录

```text
data/render-backgrounds/
├─ manifest.json
└─ generations/
   └─ YYYYMMDDhhmmssSSS-随机后缀/
      ├─ 01-<sha256>.jpg
      ├─ ...
      └─ 10-<sha256>.jpg
```

`manifest.json` 保存本次最快接口、全部测速结果、生成时间、图片 SHA-256 和字节数。渲染路径只读取清单指向的本地文件，不调用网络接口。

图片文件名并非固定值，而是“批次内序号 + 内容 SHA-256 摘要”。每天更新后 `manifest.json` 会同步记录新批次目录和全部新文件名，因此文件名变化不会造成查找失败。渲染期间若旧文件刚好被轮换，Provider 会重新读取最新清单；若清单中的文件缺失或大小不符，插件会自动重建完整图片池。

## 首次安装与每日轮换

1. 插件加载并补全 `global.yaml` 的新字段。
2. 检查清单和本地文件；图片池为空时，并行请求所有候选接口并下载实际图片测速。
3. 按速度排序，优先从最快接口取图；重复或失败时重试，必要时由下一可用接口补足。
4. 10 张图片全部校验完成后发布新批次并写入清单；旧批次在约 60 秒宽限期后清理。
5. 每日任务按 `background_refresh_cron` 重复测速和轮换。

若日志出现“背景池仅获得 N/10 张”，插件会继续使用上一批文件，并进入同日退避重试链。

每日任务失败后，默认会在 10 分钟后进行第二次尝试；仍失败则分别再等待 30、60 分钟。任意一次成功都会结束本轮重试链并正常轮换图片；全部尝试失败时仍保留上一批，等待下一次每日任务。修改锅巴里的间隔后，下一次失败链会读取新配置。
